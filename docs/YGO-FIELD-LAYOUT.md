# 유희왕 필드 구조 — 조사와 우리 구현 반영 (2026-11-17)

> 목적: 새 클라이언트 렌더러가 **실제 유희왕 필드**와 일치하도록 기준을 고정하고, 현재 구현의 모자란 부분을 목록화한다.
> 근거: ocgapi_constants.h 의 `LOCATION_*`, EDOPro `materials.cpp`/`gframe` 배치, 공식 룰(EMZ/펜듈럼).

## 1. 필드 전체 배치 (한 플레이어 기준)

```
        ┌──────────────── 상대 진영 (180° 회전) ────────────────┐
        │ [엑덱][필드][  ST ][  ST ][  ST ][  ST ][  ST ][묘지][덱]│
        │            [ MC ][ MC ][ MC ][ MC ][ MC ]              │
        │                    [EMZ]      [EMZ]                    │  ← 공유 2칸
        │            [ MC ][ MC ][ MC ][ MC ][ MC ]              │
        │ [덱][묘지][  ST ][  ST ][  ST ][  ST ][  ST ][필드][엑덱]│
        └──────────────── 내 진영 ──────────────────────────────┘
```

**내 진영(아래) 왼쪽→오른쪽**: 엑스트라 덱 · 필드 마법 존 · 마법/함정 존 ×5 · 묘지 · 덱
**상대 진영(위)**: 좌우 반전(덱이 왼쪽 끝)

| 존 | 개수 | 위치 | 비고 |
|---|---|---|---|
| **메인 몬스터 존** | 5 | 몬스터 줄 | 일반/특수 소환 |
| **엑스트라 몬스터 존(EMZ)** | **2 (양쪽 공유)** | 두 몬스터 줄 사이, 2·4번째 열 | **한 플레이어가 동시에 1칸만** 사용 가능 |
| **마법/함정 존** | 5 | 마함 줄 | 세트/발동 |
| **펜듈럼 존** | (마함 좌·우 끝) | 마함 1번·5번 칸 | **별도 칸이 아니라 마함 양 끝을 재사용** |
| **필드 마법 존** | 1 | 마함 줄 바깥(왼쪽) | 필드 마법 1장 |
| **묘지(GY)** | 1 더미 | 마함 줄 오른쪽 | |
| **제외(Banished)** | 1 더미 | 묘지 옆(보통 오른쪽/아래) | |
| **덱** | 1 더미 | 맨 오른쪽 | 메인 40~60 |
| **엑스트라 덱** | 1 더미 | 맨 왼쪽(표시는 뒷면) | 15 |
| (사이드 덱) | 15 | 필드에 **표시하지 않음** — 매치 사이에만 교환 | |

## 2. 규칙 요점 (렌더러가 틀리면 안 되는 것)

1. **EMZ 는 공유** — 두 플레이어가 각각 1칸씩 쓸 수 있고, 한 플레이어는 동시에 2칸을 쓸 수 없다.
2. **엑스트라 덱 몬스터(융합·싱크로·엑시즈·링크)** 는 **EMZ 또는 링크 마커가 가리키는 메인 몬스터 존**에만 특수 소환된다. (펜듈럼 소환은 예외적으로 메인 존)
3. **펜듈럼 존 = 마함 존의 양 끝** — 펜듈럼 몬스터를 마함 존 1번/5번에 놓으면 그 칸이 펜듈럼 존이 되고, **스케일**로 동작한다. 별도 존을 그리면 안 된다.
4. **필드 마법은 1장** — 필드 마법 존은 마함 줄과 분리된 칸 1개.
5. 상대 필드는 **180° 회전**해서 그린다(카드 텍스트 방향까지 뒤집지는 않음, 배치만).
6. 묘지/제외/덱/엑덱은 **더미**로 그린다(개별 카드가 아니라 장수).

## 3. 데이터 표현 (리플레이/ocgcore 인덱스)

`ocgapi_constants.h`:

| 상수 | 값 | 우리 state 필드 |
|---|---|---|
| `LOCATION_DECK` | 0x01 | `deck[2]` (장수) |
| `LOCATION_HAND` | 0x02 | `hand[2][]` |
| `LOCATION_MZONE` | 0x04 | `mzone[2][7]` |
| `LOCATION_SZONE` | 0x08 | `szone[2][6]` |
| `LOCATION_GRAVE` | 0x10 | `grave[2][]` |
| `LOCATION_REMOVED` | 0x20 | `banished[2][]` |
| `LOCATION_EXTRA` | 0x40 | `extra[2]` (장수) |
| `LOCATION_FZONE` | 0x100 | (필드 마법) |

**중요한 인덱스 규칙**
- `mzone` 은 **7칸**: `0~4` = 메인 몬스터 존, **`5·6` = 엑스트라 몬스터 존**(좌·우).
- `szone` 은 **6칸**: `0~4` = 마법/함정 존, **`5` = 필드 마법 존**.
- 펜듈럼은 `szone` 의 `0`(왼쪽) / `4`(오른쪽) 이며, 카드의 `LScale/RScale` 로 스케일을 읽는다.
- 좌표계는 **플레이어별 상대 좌표**(내 진영이 항상 아래). 상대는 렌더 단계에서 반전.

## 4. 우리 구현 현황 (격차)

| 항목 | 현재 | 필요 |
|---|---|---|
| 메인 몬스터 존 5 | ✅ 그린다 | — |
| 마법/함정 존 5 | ✅ 그린다 | — |
| **엑스트라 몬스터 존 2** | ❌ **없음** | `mzone[5]·[6]` 을 두 몬스터 줄 사이에 그린다 |
| **필드 마법 존** | ❌ 없음 | `szone[5]` 를 마함 줄 바깥에 그린다 |
| **덱/엑덱/묘지/제외 더미** | ⚠️ 텍스트(장수)만 | 더미 사각형 + 장수 표기 |
| **펜듈럼 존 표시** | ❌ 없음 | 마함 1·5번 칸에 펜듈럼 표시(스케일 숫자) |
| 상대 180° 반전 | ⚠️ 위/아래만 | 좌우도 반전(엑덱↔덱) |
| 사이드 덱 | — | 필드에 그리지 않음(의도) |

## 5. 적용 계획 (이번 반영분)

- `src/render/field.ts` 신규: **필드 좌표 계산 단일 소스**(존 rect + 라벨)
  - `mzone[0..4]` → 메인 줄, `mzone[5..6]` → EMZ(중앙, 2·4열)
  - `szone[0..4]` → 마함 줄, `szone[5]` → 필드 마법(마함 줄 왼쪽)
  - 덱/엑덱/묘지/제외 더미 + 장수
  - 펜듈럼: `szone[0]/[4]` 에 펜듈럼 몬스터가 있으면 `P` 배지(스케일 자리)
- `main.ts` 는 `layoutField()` 가 준 사각형에 **상태만 채워** 그린다(좌표 하드코딩 제거).
